# 关键问题修复总结

## 问题诊断

当前算法存在5个致命问题，其中**奖励设计问题**最为严重，导致：
- 模型优化错误目标（绕圈刷奖励 vs 收集宝箱）
- 训练信号被噪声淹没（11项奖励 → 梯度混乱）
- 收敛困难（需要数百万步才能学会基本策略）

---

## 已实施的关键修复

### 1. 奖励重构（最重要）

#### 原设计问题
```python
# 11项奖励，量级失衡
存活奖励: 0.04/步 → 累积40分 (48%)
宝箱接近: 1.0/步 → 累积200分 (240%)  # 问题！
宝箱收集: 5.0/次 → 5-15分 (18%)      # 被淹没
风险惩罚: -0.45/步 → 累积-50~-200分
终局奖励: 5.0/次 → 5分 (6%)          # 微不足道
```

#### 新设计原则
1. **简化为3个核心奖励**：收集宝箱、危险惩罚、终局奖励
2. **放大关键信号**：宝箱收集从5分→50分（提升10倍）
3. **移除噪声**：删除存活、里程碑、移动、技能等8项冗余奖励

#### 新奖励设计
```python
# 核心1: 宝箱收集（主导信号）
treasure_reward = 50.0 * collected  # 提升10倍，确保主导地位

# 核心2: 危险惩罚（即时反馈，仅在真正危险时触发）
if distance < 0.15:  # 仅在<27格时惩罚
    risk_penalty = -0.5 * (danger_level ** 2) * 20  # 最高-5.0

# 核心3: 弱引导信号（帮助学习，但不主导）
treasure_guide = 0.1 * dist_delta  # 每步最多0.1分（收集=50分）

# 终局奖励（大幅提升）
terminated: -50.0  # 死亡强惩罚
survived: 20.0 + treasure_count * 10.0  # 存活+宝箱加成
```

#### 预期效果
| 指标 | 优化前 | 优化后 | 提升 |
|------|--------|--------|------|
| 宝箱收集占比 | 18% | **80%+** | 4.4倍 |
| 噪声奖励项数 | 8项 | **0项** | - |
| 终局信号占比 | 6% | **20%+** | 3.3倍 |
| 信号清晰度 | 差 | **优秀** | - |

### 2. 探索策略优化

#### 问题
- 熵目标过高（0.75）→ 初期接近随机探索
- 游戏中80%动作无效（撞墙、转圈）
- 探索预算浪费在无效动作

#### 修复
```python
# 降低熵目标
TARGET_ENTROPY_RATIO = 0.5  # 原0.75

# 效果：初期探索更聚焦，减少无效动作
# 目标熵：0.75*log(10)=1.73 → 0.5*log(10)=1.15
```

#### 预期效果
- 无效探索减少 **30-40%**
- 早期能力提升（30k步开始有效学习）

---

### 3. 训练架构优化

#### 问题
- 预热不足（4000样本）
- 批大小过大（1024）
- 学习率衰减过早（100k步）

#### 修复
```python
# 缓冲区与批大小
REPLAY_BUFFER_SIZE = 50_000  # 原20k
BATCH_SIZE = 512             # 原1024
LEARNING_STARTS = 10_000     # 原4000

# 学习率调度
INIT_LEARNING_RATE_START = 5e-4  # 原3e-4
INIT_LEARNING_RATE_END = 1e-5    # 原3e-5
LR_DECAY_STEPS = 200_000         # 原100k

# 梯度裁剪
GRAD_CLIP_RANGE = 1.0  # 原0.5
```

#### 预期效果
- 样本多样性提升 **2.5倍**（50k vs 20k）
- 更新频率提升 **2倍**（512 vs 1024）
- 学习率衰减延后 **2倍**（200k vs 100k）

## 为什么这次修复会有效？

### 1. 解决了根本问题
- **之前**：奖励设计错误 → 模型优化错误目标
- **现在**：清晰的奖励信号 → 模型优化正确目标

### 2. 放大了有效信号
- **之前**：宝箱收集=5分，接近奖励累积=200分
- **现在**：宝箱收集=50分，引导信号=0.1分/步

### 3. 减少了噪声干扰
- **之前**：11项奖励 → TD目标方差大
- **现在**：3项奖励 → TD目标方差小

### 4. 优化了探索效率
- **之前**：熵目标高 → 80%时间在无效探索
- **现在**：熵目标低 → 聚焦有效动作
